# Commit Message Guide

Use conventional and consistent commit messages.

## Format
`<type>(<scope>): <message>`

## Types
- `feat` → new problem or new code
- `docs` → README/notes/template updates
- `refactor` → code improvements without behavior change
- `fix` → bug or edge-case correction

## Examples
- `feat(two-pointers): add Two Sum II`
- `feat(stack): add Valid Parentheses`
- `docs(two-pointers): improve README`
- `docs(sliding-window): update interview notes`
- `refactor(binary-search): improve Java solution`
- `fix(prefix-sum): correct edge case`
